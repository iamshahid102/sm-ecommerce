4. SECURITY / QUALITY BASELINE
--------------------------------------------------------------------------------

Implemented in code and migrations:
- RLS enabled on every public table; policies for anon/authenticated/admin and
  service-role bypass where appropriate.
- Customer-owned rows auth.uid() se scoped.
- Shopping tables block/role checks.
- Service-role key sirf backend par; frontend bundle mein nahi.
- Express: Helmet, strict CORS allow-list, global rate limit, login/contact/
  review/order-specific limits.
- Zod validation on API bodies/queries; strict schemas where needed.
- Supabase JWT verification + server-side profile/role checks.
- CMS HTML server-side sanitized; allowed tags/attributes/schemes restricted.
- Upload limits and MIME allow-list; memory storage, bucket path control.
- Admin write audit logs (actor, action, entity, changes, IP, user agent).
- No secrets committed; .env files ignored.
- Transactional email HTML interpolation `escapeHtml` se escaped; status notes
  line breaks `<br>` ke sath escaped.
- Account/profile changes role/is_blocked protected by DB trigger.
- One admin enforced by DB partial unique index.
- Dependency audit after fixes:
  backend production dependencies: 0 vulnerabilities
  frontend production dependencies: 0 vulnerabilities
  (multer 2.5.0, sanitize-html 2.18.1; Jest config updated for ESM transform)

Important security caveat:
- RLS, storage buckets, auth flows aur `place_order` ko live Supabase par test
  nahi kiya gaya. Code review + unit tests security claims ko support karte hain,
