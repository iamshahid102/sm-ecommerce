ISSUES, ERRORS AUR UNKE RESOLUTIONS
-----------------------------------
1) PowerShell mein "vercel" command block ho rahi thi
   Error:
   - PowerShell execution policy ki wajah se vercel.ps1 script run nahi hoti thi.
   Resolution:
   - Har command "vercel.cmd" ke through run ki, e.g. vercel.cmd deploy.
   - Is se CLI ka same behaviour mila aur execution-policy error khatam hua.

2) Monorepo ko single Vercel project ki tarah deploy karna
   Issue:
   - Root mein frontend aur backend dono hain; ek hi project se dono ko
     sahi tarah build karna confusing tha.
   Resolution:
   - Do alag Vercel projects banaye: smstoreweb aur smstoreweb-api.
   - Frontend ko frontend/ directory se link/deploy kiya.
   - Backend ko backend/ directory se link/deploy kiya.
   - Is se builds isolated hain aur environment variables bhi alag hain.

3) Backend Express app Vercel par 500 de raha tha
   Error:
   - FUNCTION_INVOCATION_FAILED
   - Vercel logs mein asal wajah thi:
     ERR_REQUIRE_ESM: require() of ES Module htmlparser2/dist/index.js
     from sanitize-html/index.js not supported.
   Resolution:
   - sanitize-html 2.18.1 rakha gaya.
   - npm "overrides" ke through htmlparser2 ko 10.1.0 par pin kiya.
   - htmlparser2 10.1.0 CJS require aur ESM import dono support karta hai,
     is liye Vercel ke CJS function bundle mein crash khatam hua.
   - Pehle 2.17.0 pin karne ki koshish bhi ki gayi thi, lekin woh htmlparser2 8
     use karta hai aur security fix se peeche ho jata. Is liye final solution
     override wala rakha gaya.
   - Backend tests 65/65 pass hue aur real /api/v1/pages/about CMS content bhi
     sanitize ho kar successfully load hua.

4) Backend ke nested API routes Vercel par 404 de rahe the
   Error:
   - /api/v1/health aur /api/v1/products 404 return kar rahe the.
   - Catch-all file api/[...path].js sirf ek path segment par route ho rahi thi.
   Resolution:
   - Catch-all function remove kiya.
   - Single entry backend/api/index.js rakhi.
   - vercel.json mein rewrite lagaya: /(.*) -> /api
   - Ab /api/v1/health, /api/v1/products, /api/v1/pages, etc. sahi chal rahe hain.

5) Backend root URL par 500 aa raha tha
   Error:
   - https://smstoreweb-api.vercel.app/ par FUNCTION_INVOCATION_FAILED.
   - Vercel Express framework preset src/app.js ko auto-detect kar ke apna
     root index function bana raha tha, jis se conflict ho raha tha.
   Resolution:
   - backend/vercel.json mein "framework": null set kiya.
   - Rewrite ke through root aur API dono api/index.js par gaye.
   - Ab root URL 200 return karta hai.

6) Backend deploy ke baad Vercel ka internal rewrite warning
   Warning:
   - Vercel ne bataya ke internal rewrites ab destination path se route karte hain.
   Resolution:
   - Rewrite ke baad actual requests test kiye.
   - Express ko original URL mil raha hai; /api/v1/health aur nested routes 200 hain.
   - Koi extra workaround ki zaroorat nahi padi.

7) Frontend environment variables ka production API se connect hona
